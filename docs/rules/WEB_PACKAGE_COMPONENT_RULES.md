# Mandatory Web Package Component Rules

تسري هذه القواعد الإلزامية على كافة مهندسي ووكلاء التطوير لـ `packages/CampusFind/Web`.

---

## 1. الفحص والتحقق والالتزام بالمكوّنات القياسية

1. **فحص المكوّنات الحالية**: يجب فحص `packages/CampusFind/Web/src/Web/Resources/views/components` قبل كتابة أي markup جديد.
2. **حظر إنشاء مكوّنات مخصصة أو markup يدوي في الواجهات**: يُحظر تماماً كتابة أزرار، بطاقات، شارات، تنبيهات، حقول إدخال، نوافذ منبثقة، تبويبات، أو قوائم منسدلة بشكل يدوي كـ raw HTML داخل صفحات الواجهة عند وجود مكوّن قياسي متاح في `<x-web::...>`. يجب استهلاك المكوّنات الموحدة حصراً في كافة صفحات الويب.
3. **الاستناد إلى حاجة فعلية**: لا يجوز إنشاء مكوّنات افتراضية غير مستهلكة في قوالب الحزمة.
4. **الاستقلال التام عن presentation لوحة الإدارة**: يُمنع استيراد مكوّنات العرض من `Webkul\Admin` (مثل `<x-admin::...>`) داخل واجهات `Web`. النمط المعماري يُستنسخ داخل حزمة `Web` بصورة مستقلة تماماً.

---

## 2. النمط المعماري القياسي للمكوّنات (The Admin Reference Pattern)

يجب على المكوّنات التفاعلية في حزمة `Web` اتباع نفس النمط المعماري المعتمد في حزمة `Admin`:

1. **التهيئة والخصائص**: استخدام `@props` لتعريف الخصائص الافتراضية بدقة.
2. **تمرير السمات**: استخدام `$attributes->merge()` لتمرير فئات CSS وسمات HTML الأساسية.
3. **مساحة الأسماء (Namespace)**: استخدام البادئة `x-web::` (مع دعم الاسم المستعار `x-campusfind_web_web::` للتوافقية).
4. **عناصر Vue التفاعلية**: استخدام وسوم مكوّنات Vue المخصصة (مثل `<v-accordion>`, `<v-modal>`, `<v-dropdown>`, `<v-tabs>`, `<v-flash-group>`).
5. **القوالب الافتراضية للتحميل (Shimmers)**: تضمين مكوّن Shimmer فرعي مناسب (مثل `<x-web::shimmer.accordion />`) ليعمل كـ placeholder أثناء تحميل Vue.
6. **الفتحات المسماة والمحددة النطاق (Scoped Slots)**: ربط فتحات Blade المسماة بفتحات Vue مع تمرير متغيرات الحالة والدوال (مثل `v-slot:header="{ toggle, isOpen }"`).
7. **قوالب `text/x-template`**: تعريف قوالب Vue داخل وسوم `<script type="text/x-template" id="v-*-template">`.
8. **منع تكرار السكربتات**: تغليف القوالب وتسجيل المكوّنات (`app.component('v-*', {...})`) دائمًا داخل `@pushOnce('scripts')` لضمان عدم تكرار التسجيل عند وجود حالات متعددة لنفس المكوّن في الصفحة.

---

## 3. معمارية وقت التشغيل (Runtime Architecture)

- **تطبيق Vue موحد**: يُنشأ تطبيق Vue العام في `packages/CampusFind/Web/src/Web/Resources/assets/js/app.js` عبر `window.app = createApp({...})`.
- **المكونات الإضافية**: يتم تثبيت `$emitter` و`$web` لدعم أحداث التنبيهات وإدارة النوافذ المشتركة.
- **التركيب في القالب العام**: يحتوي `layouts/index.blade.php` على الحاوية الجذرية `<div id="app">`، ويقوم بتركيب التطبيق `app.mount("#app")` عند اكتمال تحميل الصفحة `window.addEventListener("load", ...)` بعد إتاحة كافة قوالب `@stack('scripts')`.
- **أحادي المثيل وعدم التضارب**: يُمنع إنشاء مثيلات Vue مكررة أو منافسة في الصفحات.

---

## 4. الهوية البصرية والتصميم (Visual Identity)

- **الرموز التصميمية لـ CampusFind**: الحفاظ على ألوان العلامة التجارية (اللون الزمردي/البترولي `#185c54`، ولون النعناع `#e6f4ee`، وتدرجات `slate`، وخط Cairo).
- **الوضع الليلي والنهاري**: دعم الوضع الداكن عبر فئات Tailwind `dark:*` وحفظ التفضيل في cookie آمنة.
- **ثنائية الاتجاه (RTL / LTR)**: دعم كامل ومجرب للعربية والإنجليزية باستخدام الأدوات الدلالية الموجهة (`ltr:*` و`rtl:*`).

---

## 5. معايير الوصول (Accessibility & Semantics)

- **أزرار وعناصر تفاعلية أصلية**: استخدام عناصر `<button>` و`<a>` الأصلية وتجنب `div` غير المعرف دلالياً.
- **حالات ARIA المتزامنة**: ربط سمات `aria-expanded` و`aria-controls` و`aria-haspopup` و`role="tabpanel"` و`role="dialog"` بحالة المكوّن.
- **إدارة التركيز والمفاتيح**: دعم مفتاح `Escape` لإغلاق النوافذ والقوائم، ومفتاحي `Enter` و`Space` لتفعيل الـ disclosures.

---

## 6. التعريب واللغات (Localization)

- **منع النصوص الثابتة**: يُمنع كتابة أي نص ظاهر للمستخدم أو تسمية ARIA بشكل ثابت (Hardcoded).
- **التكافؤ الكامل بين اللغات السبع**: يجب توفير المفاتيح لكافة اللغات السبع المعتمدة (`ar`, `en`, `es`, `fa`, `pt_BR`, `tr`, `vi`).

---

## 7. الاختبارات الإلزامية

قبل اعتماد أي مكوّن جديد أو ترحيل مكوّن قائم:
1. إضافة اختبارات العرض وتمرير السمات والقوالب في `packages/CampusFind/Web/tests/Feature/Web/WebComponentArchitectureTest.php`.
2. التحقق من منع تكرار السكربتات عبر `@pushOnce`.
3. التحقق من استقلال الحزمة وعدم وجود أي إشارة لـ `x-admin::`.
4. تشغيل حزمة اختبارات Web بالكامل والتأكد من نجاحها 100%.
5. التحقق من نجاح بناء الأصول للإنتاج عبر `npm run build`.
